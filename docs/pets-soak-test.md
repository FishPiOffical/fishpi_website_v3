# 宠物八小时本地持续测试

本轮验证 `pet` 分支第六批完成后的稳定性。运行脚本为 `tools/pets-soak.mjs`；测试期间不发布代码、不改生产配置、不操作真实用户账号。八小时是实际持续观察时间，不能用快速循环、修改系统时间或把七天模拟结果换算成八小时。

本文同时列出运行门槛和结果判定要求。是否已经完成，必须以对应运行目录的报告为准；启动成功、专项通过或服务运行八小时，都不等于八小时测试通过。

## 测试分层与覆盖

三种验证分别记账，不能互相替代：

| 层次 | 执行内容 | 可证明的范围 | 不可据此宣称 |
| --- | --- | --- | --- |
| 前端专项 | `npm run test:pets`：API/store、真实 Vue 模板、桌宠定位 | 协议、身份隔离、原键恢复、状态更新和指定交互断言 | 真实浏览器绘制、真实移动设备键盘、真实后端已接受操作 |
| Rhythm 专项 | 本地宠物服务、事务与接口测试 | 并发唯一性、消费/发奖一致性、边界及故障处理 | 所有自然计时活动都在这八小时实际完成 |
| 本地 HTTP 路线 | 专用测试账号访问本地运行中的 Rhythm | 当前发布代码、自然等待、真实数据库状态和幂等回放 | 未走到的地点/课程/工作、并未实际触发的跨日或断线场景 |

UI 专项编译实际组件，仅替换传输。桌宠专项使用 JSDOM、受控元素几何和 `visualViewport`，不是无头浏览器截图。第六批已有的桌面/窄屏浏览器验收属于独立证据，见 [第六批记录](pets-phase-six.md)，不能把那次截图算成本轮持续浏览器监控。

| 范围 | 核对点 | 主要证据 |
| --- | --- | --- |
| 领养与命名 | 四选一、重复领养/重复点击、合法名字、身份切换隔离 | 前后端专项；HTTP 路线实际采用的宠物另记 |
| 日常照顾与成长 | 饱食/水分/心情/精力、冷却、每日成长上限、等级进度与封顶、旧目录缺成长字段 | 前后端专项；HTTP 状态差异 |
| 资产与补给 | 宠物币非负、背包实际变化、每日补给不重复、工作共享产币上限 | 事务专项；HTTP 前后快照和日志 |
| 外出/学校/工作 | 单活动位置、门槛、冻结成本奖励、到期显式领取、职业熟练度与技能分离 | 专项覆盖全部目录；HTTP 自然计时的活动逐项列出 |
| 手作、商店与旅程 | 消耗与收藏一致、已收藏不可重复购买、旅程按序推进且奖励只领取一次 | 前后端专项；HTTP 仅记录实际执行项 |
| 重新领养 | 明确确认、512 币、成长重置、资产/额度/旧日志保留、不能重领首次奖励 | 前后端专项；不默认重置用户试玩宠物 |
| 弱网与未知结果 | 超时/正文断流保留原命令和原键；写成功后读取失败只能重读；401/429 后停止自动重复请求 | 注入故障专项；真实异常若出现单独保留证据 |
| 读取调度 | 聚焦/联网/多标签合并，日志只展开才读，退避，无几何触发网络请求 | API/store 与 UI 专项 |
| 桌宠与移动端 | 320/390px、短视口、横竖屏、导航/浮窗/输入避让、模态增删及仅切显示、退出身份、反复挂卸清理 | 桌宠真实组件专项；软键盘和样式另需真机/浏览器 |
| 长时间运行 | 服务、源码与测试进程保持同一基线，轮次不重叠，真实活动自然到期，异常停写 | 心跳、轮次日志、HTTP 事件、最终报告 |

截至本轮文档编写，桌宠专项扩展为 11 组。持续报告应解析每次实际输出与退出码，不能写死历史测试数量。未触发的跨日、浏览器后台节流、真机键盘、真正长时间 DOM 内存增长等项目应标为“未覆盖”，不能补成通过。

## 运行前检查

1. 两个仓库都在 `pet` 分支，记录提交号、受测源码摘要及开始时间。摘要包含检查范围内已跟踪的差异与新增未跟踪文件；被 Git 忽略的构建产物不在监控范围。确定性专项和构建先通过；本轮基线之后禁止热更新产品代码，也不能在后台替换未监控的构建产物。
2. 前端固定 `http://127.0.0.1:5173`，Rhythm 使用本地约定端口 `http://localhost:8081`。明确验证监听进程及本地数据库身份，端口被其他服务占用时停止，不自行杀进程或换端口。
3. HTTP 测试目标只允许准确的回环地址及已确认端口，不接受外网域名，也不跟随重定向到外部。前端开发代理默认可能指向现网，必须核对实际配置；不得因为请求从本地发起，就认为请求目的地也是本地。
4. 创建本轮专用账号/宠物数据并记录其非敏感标识。所有写操作限定这些标识；不能沿用用户正在试玩的 admin 或其他账号，不清空整个本地数据库，不改系统时钟和全站规则。
5. 测试权限仅用于本地宠物流程。凭据不出现在命令参数、源码、事件记录或报告中；必要的本地运行凭据文件必须位于忽略目录、限制文件权限，终止后按实际恢复需要处理。
6. 确认仅有一个持续测试运行实例。运行目录与子进程带本轮标识，避免两次测试同时消费同一宠物的资源。

本轮允许测试专用数据发生真实养成变化。后续清理仅按本轮账号和宠物标识进行，先保留核对所需日志，不使用全表删除或覆盖其他账号数据。

## 节奏与八小时判定

默认连续运行 8 小时。前端专项每 15 分钟一轮，Rhythm 专项每 60 分钟一轮；目标不少于一小时的运行，在结束前五分钟再安排一次完整后端基线。首次与末次完整基线均需完成。本地 HTTP 活动路线以 60 秒节流调度，全部四个测试账号共用每分钟 30 次请求上限，按当前快照及活动结束时间决定是否操作。不要把调度周期等同于“每次强制发送所有接口”。

- 前一轮未结束，不并发叠加下一轮；实际开始/结束与耗时写入专项事件和报告。周期是调度目标，耗时过长会推迟下一轮；核对实际轮次，不能把未执行的计划轮次补算为通过。失败不能被后续成功覆盖。
- 自然活动按服务器 `endsAt` 等待，到期后显式领取；不提前改数据库中的活动时间，不反复点击领取探测到期。
- 正常业务路线根据当前余额、库存、体力、技能和占用状态选择可执行操作。条件未满足记录为未执行，不用修改账号数值伪造完成。
- 记录开始、结束、心跳间隔、最长调度空档、各层实际完成/失败/中断轮次，以及真实 HTTP 请求和断言。业务拒绝、传输失败和未确认操作通过 HTTP 事件与待核对文件复核；未独立统计的项目不能伪造数量。
- 每 15 秒记录心跳；机器睡眠、进程挂起、重启或心跳空档超过 120 秒时，该段必须记为中断。唤醒后不能以墙上时钟已经过去八小时直接判通过，也不能把短时间密集补跑当成缺失观察时间。
- 受监控源码（含新增未跟踪文件）、服务 PID/启动身份或监听端口发生变化时停止写操作，并把本轮标为中断/阻断；HTTP 目标固定为本地，不能混合不同版本。运行器不监控已忽略的构建产物，因此这类文件必须在测试期间保持不变，报告不能声称对此已有自动保护。
- 最终通过要求：同一基线连续有效观察不少于八小时、各层必要轮次完整完成、没有未解释失败或未知操作、实际状态与账本/日志一致。各指标的实际值、阈值和证据路径写入报告。

若测试只完成了部分时长，应写“已运行 X 小时，尚未完成”，而不是“八小时测试通过”。确定性时间推进测试仍可验证跨日逻辑，但必须与本轮自然时间观察分开列出。

## 错误与停写规则

| 事件 | 测试器行为 | 报告要求 |
| --- | --- | --- |
| HTTP 401、403、429 或风控/验证码响应 | 立即停止后续全部真实 HTTP 请求，不循环登录、不换账号/IP绕过、不转到生产；保存进度等待核对 | 时间、接口路径、状态/业务码、停止原因；不保存令牌或敏感正文 |
| 写接口超时、断流或回执丢失 | 立即停止后续全部真实 HTTP 请求，保留原方法、目标、请求内容及幂等键，不自动恢复；后续人工核对只能使用同一命令 | 是否已确认、待核对命令、状态/日志核对结果；最终仍有 pending 文件即不能通过 |
| 写成功、随后状态读取失败 | 真实 HTTP 路线立即停止后续请求，保留待核对信息，不自动重写或重读 | 分开记录“写已确认”和“当前状态未读取”；前端仅重读的行为由隔离专项验证 |
| GET 503、超时或正文断流 | 立即停止后续全部真实 HTTP 请求，不自动退避重试；失败不记为空状态 | 实际错误与停止时间；有限退避及恢复仅由前端故障专项覆盖 |
| 业务条件不满足 | 停止该操作，根据当前状态等待或选择合法路线；不为提高覆盖率篡改数值 | 明确业务拒绝或未覆盖，不能计为成功 |
| 未确认命令 | 真实路线停写后不自动恢复，保留原键与内容；不得用重新领养、重建账号或清空数据抹平 | 未确认操作清单与最后安全状态，最终有 pending 则失败 |
| 服务退出/目标变化/源码变化/机器睡眠 | 停止新写入及后续轮次，保留已有证据 | 中断时刻、有效时长、是否存在在途命令 |

真实 HTTP 路线遇到上述异常会停止全部后续 HTTP 请求；运行器可继续执行没有真实站点写入的隔离专项以收集诊断，不能因此抹掉真实链路失败。已成功写入后的同键回放只用于主动验证幂等，不是对未知结果的自动重试。

故障注入只在隔离专项/夹具里运行，不通过封禁网络或破坏用户正在用的本地服务制造故障。真实接口异常应如实记录，不改返回码以让报告变绿。

## 启动、状态和停止

入口提供 `start`、`status`、`stop`。具体参数以同版本 `tools/pets-soak.mjs` 的用法说明为准；不手动执行未经核对的旧脚本或临时数据库命令。

在 website_v3 项目目录执行，按实际路径指定本地 Rhythm：

```bash
node tools/pets-soak.mjs start --hours 8 --rhythm /Users/ling/Documents/GitHub/rhythm
```

启动后测试进程独立运行，关闭当前终端不应视为停止。查看最近一轮、或请求停止最近一轮：

```bash
node tools/pets-soak.mjs status
node tools/pets-soak.mjs stop
```

要操作指定历史运行，在 `status` 或 `stop` 后加 `--run` 和启动时输出的完整运行编号。省略编号时采用 `.temp/pet-soak/latest.json`，不是自动查找仍在运行的所有进程，操作前先核对编号。

`--hours` 默认 8，可接受大于 0、不超过 24 的时长。短时 smoke 只能验证启动、报告与停止链路，不是八小时通过；报告须同时显示实际目标时长。任何恢复都创建新 run，不自动接着旧 run 累加时间。

停止请求通过运行目录中的 `STOP` 文件传递：下一次心跳发起收尾，并停止新操作，等待本轮子进程有界退出后释放运行锁。只停止本测试器，不顺带结束 Rhythm、前端或用户其他进程。不要用 `kill -9` 作为正常停止方式；若异常强制结束，必须保留中断状态并确认子进程全部退出后才能处理遗留锁。

macOS 运行器用 `caffeinate -i` 防止空闲自动休眠；它不等于能阻止合盖、手动睡眠、断电或系统重启。上述中断仍按心跳缺口判定。

本轮输出保存在忽略目录：

```text
.temp/pet-soak/<runId>/
  config.json          本轮基线、目标与时间参数
  state.json           当前状态、心跳、轮次与停止原因
  events.jsonl         调度与专项事件记录
  live-summary.json    本地 HTTP 路线状态与断言计数
  live-events.jsonl    HTTP 请求元数据与断言记录
  report.md            本轮报告
  *-*.log              各专项原始输出与退出证据
  accounts.private.json  仅本机受限凭据文件，不属于报告、不分享
  pending-*.json       未确认操作原命令，只用于核对恢复
```

若进程意外退出，先用状态命令核对最后心跳、子进程和未确认写入，再恢复服务。默认重新启动新的一轮，旧轮次保留“中断”结论，不拼接成连续八小时。恢复未知业务操作时仍使用旧命令原键；若尚不能确认旧结果，禁止先启动会继续写同一账号的新路线。报告不能因手工修改 `state.json` 或删除失败事件而恢复为通过。

## 报告内容

最终报告至少包括：

- 运行标识、两仓源码基线与实际本地目标、开始/结束/有效观察时间、最长心跳间隔。
- 前端专项、Rhythm 专项和 HTTP 路线分层汇总：实际完成/失败/中断，退出码、耗时、对应证据文件；结合调度目标核对缺失轮次，不把未执行计为成功。
- 自然完成的活动名称与服务器时间、实际奖励、账户余额/背包/技能/职业/收藏/旅程变化；未执行项目单列。
- 故障及原键恢复过程，是否存在重复扣费、重复发奖、负资产、状态回退、跨账号数据或未知命令。
- 服务中断、受监控源码变更、睡眠或环境变化，以及是否因此提前停止；未监控的忽略构建产物单独声明。
- 每五分钟采样本地前后端服务的 RSS、CPU 和文件描述符数；报告列出 RSS 范围与首末变化。缓存、垃圾回收都会影响 RSS，这些数据仅作观察，不自动判定存在或不存在内存泄漏。
- 结论只采用“通过”“失败”“中断/阻断”“未完成”等与证据相符的状态，写明剩余人工验收：真机键盘、实际浏览器长时间性能与动画不属于这次无头持续专项。

本地持续测试通过不等于允许部署；仍需按项目要求进行人工体验与发布确认。

## 覆盖补强与针对性复测

八小时测试与针对性测试分开保存，不能用后来补跑的结果改写原运行的覆盖率。自然长跑不改时间或资产；针对性 HTTP 专项仅使用新建的本地 `petSoak` 账号和明确记录的数据库夹具，推进活动时间以在有限时间内检查全部目录及领取路径。夹具不修改生产代码、目录规则、冻结成本/奖励或系统时钟，也不处理历史八小时账号。

新增检查要求：

- 「陪伴的日常」按喂食、饮水、玩耍依次推进，核对每一步与整链奖励；同键重放成功、换键重复领取被拒绝且不再次发奖。
- 成果领取核对冻结经验、宠物币及共享日限、口粮和材料、课程技能、独立职业熟练度/完成次数、心情上限。自然衰减和公开数值舍入单独计算，不把这些正常变化当成资产变更。
- 明确拒绝的写入前后，钱包、背包、成长、收藏、旅程、冷却及活动快照保持不变；休息同键重放保留起止时间，只允许已经到期的休息自然结束。
- 实际读取日志与活动历史的全部分页，验证页码、总数、顺序、跨页去重、活动冻结/实际奖励对应，以及成功命令与日志净增量一致。针对性测试另与本地账本核对；明确的测试资金偏移单列，不冒充业务收入。
- 测试断言本身使用故障样本回归，确保漏发材料、少发技能、重复消费、重置休息时间、重复或缺失分页等错误确实会使检查失败。

后端汇总直接读取结构化结果，分别列出基线测试类、不变量检查次数、并发场景，不能混为 PASS 组数。正常截止、手动停止、访问受限、服务异常、断言失败及残留待核验命令分别记录；正常截止不再出现在“问题与中断”中。重新渲染历史报告应另存副本，保留原始 `state.json`、HTTP 事件和旧报告。

工具的报告回归命令：

```sh
node tools/pet-soak/report-test.mjs
```

具体针对性复测命令、覆盖和结果见 [补测记录](pets-soak-targeted-review.md)。本批只修测试与报告，不修改宠物业务规则，也不重新开始八小时任务。
