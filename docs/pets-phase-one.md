# 宠物家园：第一批基础养成

本文保留第一批范围与验证记录；后续外出、学校和技能成长见 [第二批工作记录](pets-phase-two.md)。

本批在本地 `pet` 分支开发，前端基线 `bbe0665`，Rhythm 基线 `0c6e26ef`。不自动推送、部署或执行业务库迁移；本地提交与专项通过不代表用户已经人工验收。

## 已接入范围

- `/pets` 为本人家园，游戏页提供入口。游客可看领养说明，登录后读取本人真实状态。
- 摸摸獭、荷小豚、鱼饼喵、派小鱼免费四选一，每账号一只；领养时命名，之后可改名。
- 饱食、水分、心情、精力、等级、经验、亲密度；喂食、饮水、抚摸、玩耍、休息与唤醒。
- 独立宠物币、基础口粮背包、每日补给及口粮购买，不消费或兑换站点积分。
- 可拖动、收起、关闭并重新唤出的静态桌宠；位置与显示偏好仅保存在当前浏览器。
- 四张透明 WebP 作为第一批静态资源，256 × 256，总计 66,248 字节。暂不制作动画。

学校、外出、工作、重新领养不在本批开放范围，不出现可点击的占位入口。宠物不会死亡或离家。

## 数据与操作

前端协议独立维护在 `src/api/v3-pets.ts`，账号状态由 `src/stores/pets.ts` 共享。页面与桌宠合并初始化读取；普通路由切换复用内存数据，不逐动作查询目录，不轮询。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v3/pets/catalog` | 物种、物品与试运行规则 |
| `GET /api/v3/me/pet` | 当前宠物、钱包、背包、补给与服务器时钟 |
| `POST /api/v3/me/pet/adoption` | 首次免费领养 |
| `PUT /api/v3/me/pet/name` | 改名 |
| `POST /api/v3/me/pet/actions` | 照顾、休息、唤醒 |
| `POST /api/v3/me/pet/supplies` | 按服务器日期领取补给 |
| `POST /api/v3/me/pet/purchases` | 按目录版本购买口粮 |

写入使用内存 Bearer 与 `Idempotency-Key`，前端串行执行；服务端锁账号并执行事务，宠物、钱包、背包、账本和回执原子提交。除领养和账号补给外，命令绑定当前 `petId`，不能用旧宠物命令操作后来重新领养的宠物。

写回执只证明对应操作完成，不作为当前养成状态。确认后统一 GET；若该 GET 失败，仅重新读取，不再发送消费。结果不明时冻结原内容和原键，恢复期间的 4xx 也不丢弃未知操作。换号或退出销毁本人状态和未确认命令，正常令牌轮换保留。未知操作目前只跨 SPA 路由保留，不跨整页刷新；整页刷新后先读取服务端现状再操作。

SSR 只输出页面外壳，不读取本人宠物。钱包、背包、名字和成长不写浏览器持久缓存。跨标签页仅广播同账号失效信号，后台页返回前台时合并读取。其他设备的变动，在重新加载页面、返回前台（上次同步超过 60 秒）或手动刷新时同步；SPA 内重返家园复用内存状态。服务器负责离线衰减和休息结算，前端时钟只显示倒计时，不自行生成奖励或属性。

## 试运行规则

规则集中在 Rhythm `ApiV3PetRules`，目录版本为 `1`。前端名称与价格以目录为准。

- 首次领养：100 宠物币、6 份口粮，四项状态均为 100。
- 每日补给：20 宠物币、2 份口粮，使用北京时间日期；同日不同操作键也不能重复领取。
- 口粮每份 5 宠物币，每次购买 1～20 份；喂食恢复 35 饱食，饮水免费恢复 40 水分。
- 饱食、水分、心情分别每小时减少 2、3、1，最低为 0；保留小数余量，频繁读取不暂停衰减。需实际不足至少 1 点才可喂食或饮水。
- 抚摸恢复 10 心情，玩耍消耗 10 精力并恢复 20 心情；两者分别冷却 30 分钟。
- 喂食、饮水、抚摸、玩耍合计每天最多 10 次获得成长，每次 10 经验、2 亲密度。休息与唤醒不产成长。
- 休息最长 4 小时，每小时恢复 20 精力，可提前唤醒；休息时不能同时照顾。自然到期后的状态由服务端结算。
- 每 100 经验升一级，最高 30 级；亲密度最高 100。名字为单行 1～12 个可见字符，最多 256 UTF-16 单元，组合 Emoji 按字素计数。

## 验证

前端专项命令：`npm run test:pets`。覆盖协议校验、名字字素、游客/SSR 零读取、初始化并发合并、重复点击、写成功后读取失败、未知原键恢复、换号迟到响应及跨标签失效。

构建：`npx vue-tsc -b`、`npm run build`。后端事务、权限与离线规则专项由 Rhythm 的本批工作记录列出。

本次实际验证：

- `npm run test:pets`：11 组协议/状态专项与 5 组真实 Vue 组件专项通过，包括目录价格版本拒绝后的恢复。
- 类型检查、客户端与 SSR 完整构建通过；构建中的反馈页面静态/动态导入警告为既有警告。
- 本地 Chrome 在 1440px、390px 和 320px 下检查排版；使用隔离请求夹具走通领养、照顾、休息/唤醒、补给、购买、改名和桌宠操作。夹具只替换测试页传输，不向真实账号写入数据，临时公开入口已移除。
- 实际开发服务器 `/pets` 返回 200 和游客 SSR 外壳，四张 WebP 返回正确类型及大小，SSR 不展示本人桌宠。
- Rhythm 的六组事务/HTTP 专项、新增七路由鉴权、验证码盾及版本检查通过。全仓审计仍存在八个既有 API 文档缺口和一个既有勋章匿名访问审计问题，详情见 Rhythm 的 `docs/api-v3-pets-phase-one.md`。
- 未执行真实 MySQL 迁移、IDEA 运行态重启或真实前后端写入联调；隔离测试不替代这些验证和开发者人工验收。
