# 乱斗规则复核与可复现原型

2026-11-16，服务于[开发计划](../pet-brawl-design.md)和[经济方案](../pet-brawl-points.md)。本目录的 Python 原型仅进行规则测算，使用标准库，在本机内存运行。生产 Java 引擎尚待实现，两者之后需要同向量比对。

## 运行

从 website_v3 根目录执行，命令输出 JSON。使用 Python 3，以下命令对应已保存的报告。

```sh
python3 -B docs/pet-brawl/balance_probe.py --trials 4000 --seed 20261116
python3 -B docs/pet-brawl/balance_probe.py --trials 1000 --seed 20261117 --modes balanced
python3 -B docs/pet-brawl/balance_probe.py --trials 1000 --seed 20261118 --modes balanced
python3 -B docs/pet-brawl/growth_probe.py --trials 10000 --seed 20261116
```

报告分别为 [基础规则主报告](balance-default.json)、[第二种子](balance-seed-20261117.json)、[第三种子](balance-seed-20261118.json)和[成长敏感性](growth-default.json)。脚本见 [balance_probe.py](balance_probe.py) 和 [growth_probe.py](growth_probe.py)。

## 基础规则发现

每方案 9×9 有序配装、4,000 个随机样本，交换双方随机序列和先手后共 648,000 局。old 为修订前文档的交替先手与旧收益，balanced 为新候选，另外两个模式用于检查同时结算。

| 指标 | old | balanced |
| --- | --- | --- |
| 配装平均得分率最小值 | 37.929% | 48.589% |
| 配装平均得分率最大值 | 64.233% | 50.736% |
| 镜像首回合先手胜率最小值 | 40.975% | 48.975% |
| 镜像首回合先手胜率最大值 | 64.150% | 50.700% |

同时结算、双 KO 判平的整体平局率约 37.880%。按负残血比较过量伤害的变体降到约 4.470%，但增加规则解释成本，当前候选采用每回合随机先手、逐个行动。

候选另两次种子复验中，配装平均得分率范围分别为 48.536%–50.811% 与 48.253%–50.931%。收益相近后策略差异偏弱，未来新增克制和条件效果需继续验证全矩阵。

## 成长敏感性

把 HP 与伤害放大 100 倍为整数单位，让一方最大生命和基础攻击同时增加固定百分比，固定附加伤害、减伤和治疗量相同。每档 9 种镜像配装，各 10,000 个随机样本和交换对局，共 180,000 局。

| 同时增加 HP 和基础攻击 | 成长方平均得分率 |
| --- | --- |
| 0% | 50.000% |
| 1% | 56.313% |
| 2% | 63.853% |
| 3% | 70.822% |
| 5% | 82.568% |
| 10% | 97.129% |
| 15% | 99.773% |

这个结果说明当前低方差回合模型对属性叠加很敏感。3% 只是供后续调参的探针，生产配置还要分配到每个成长节点、测试异配装并检查观感。多系统各自增加 10% 后相乘会迅速造成悬殊对局。

## 测量边界

得分率为 (胜局 + 平局 × 0.5) / 总局数。JSON 还分别报告纯胜、负、平率。所有配装与交换局共享随机样本，总局数不能视为同等数量的独立统计样本。当前输出未包含置信区间或逐个对位明细，正式数值原型需要按种子对聚类统计并输出完整对位矩阵。

基础原型按整点伤害向下取整，成长原型保留到百分之一伤害，两者取整精度不同。成长原型当前只测同配装、双属性同时增长，尚未验证价格表中的每一级装备，也未做真实付费率、玩家余额和 NPC 通关数据检验。免费 90 活跃日成型来自材料成本算术，生产掉落和难度仍需联调验证。

## 开发依赖复核

- Rhythm 的 ApiV3PetService.mutate 先取得本人用户锁，begin 拒绝嵌套根事务。PvP 需要核对双账号全局锁序以及 ApiV3SecurityProofService 的客户端锁。
- PointtransferMgmtService.executeWithTransferLocks 要求积分锁在根事务前取得。ApiV3AppearanceShopService 同事务记录扣款、双边流水索引、权益和购买记录，可复用其约定。
- ApiV3PetRiskService 使用操作白名单，乱斗写入需显式接入。正常无对手或额度拒绝应与风控异常区分。
- website_v3 当前 pets 与 appearanceShop 的未知命令仅在内存恢复。较高金额的成长增加服务端报价订单及本人查询，整页刷新后可核对实际结果。
- 现有宠物日志、物品类别和客户端类型使用有限枚举。乱斗采用独立目录/适配器，合并家园日志时显式扩展协议。
