# 红包详情与聊天室操作提示

红包详情统一为红金色头部、领取进度、初始奖池、税额和领取记录。普通、拼手气、专属、心跳及猜拳沿用同一详情组件。猜拳使用三个独立手势按钮，选择手势后直接提交领取。心跳红包点击后直接领取。双方出拳、胜负、负积分和发送者退款仅展示当前详情接口实际返回的数据。

聊天室顶部不再常驻显示发送、红包、撤回、话题等操作的成功回执。失败、结果未确认及提交后读取失败仍提供原请求键恢复或仅重读入口；不删除 store 中的回执，不改变消费与消息协议。

## 验证

- 红包专项覆盖选手势直接领取、原键恢复、负积分和领取后当前详情刷新；撤回专项仍核验实际费用回执，仅取消成功文案展示。
- 浏览器通过本机身份与接口夹具检查普通红包、猜拳待出拳/胜负、心跳扣款、已领完、详情失败及重试；390px 宽度详情保持在视口内。
- 本机夹具预置成功回执，确认顶部无成功提示。未向真实站点发送消息或执行红包消费。

关键文件：`ChatRedPacketDialog.vue`、各 `Chat*Recovery.vue`、`tools/v3-chat-red-packets-test.mjs`、`tools/v3-chat-revoke-test.mjs`。

## 领取记录标识

领取记录沿用旧版规则：红包领完后，将金额大于零的首位最高金额领取者标为「来自老王的认可」，并列时只标记列表中的第一条。金额为 0 的每条记录显示「0溢事件」，领完前也可展示。标识使用可见文字和主题配色，新版和历史旧红包共用同一展示逻辑。

专项覆盖未领完、领完后并列最高、全部为零、负积分及旧红包切换；类型检查通过。隔离 Chrome 验证 1280px 与 390px 的明暗主题、长昵称及刷新后的标识更新。验证使用本地夹具。

## 点击直接领取

普通、拼手气、专属和心跳红包卡片点击后，先提交领取 POST，成功后再并行刷新红包详情与消息状态。猜拳点击手势直接提交所选出拳；点击猜拳卡片主体仍打开详情供选拳。心跳和猜拳随领取请求自动提交现有协议的 riskAccepted，详情中的领取按钮统一为「领取一份」，没有额外风险确认步骤。

已知领过、领完、无资格、发送者本人不可领取的红包仅打开详情。未知旧红包首次提交到 V3 领取接口被拒绝后读取旧详情，后续按只读展示。领取断流或服务端结果未知时保留原命令、正文和幂等键，显式恢复后核对结果。用户在领取期间关闭弹窗，不因成功回执重新弹出。

回归覆盖五种类型的真实卡片入口、第一条请求为 POST、成功后仅一次详情 GET、连点去重、断流恢复、关闭及旧红包回退。隔离 Chrome 在 1280px 和 390px 核对五种类型点击到领取及详情展示，接口使用本地夹具。
