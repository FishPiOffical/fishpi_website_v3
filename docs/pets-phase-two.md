# 宠物家园第二批：外出与学校

本批在两仓 `pet` 分支继续第一批养成闭环，增加三个外出地点、六门课程、六项技能和活动成果领取。仍使用现有静态宠物，不开放工作、重新领养、随机事件或新动画，不消费站点积分。

## 玩法与展示

- 家园的照顾区下方增加活动面板，可在外出与学校之间切换。各项时长、费用和成果直接读取后端目录。
- 广场散步 5 分钟、河岸探索 15 分钟、林间远足 30 分钟；课程均为 10 分钟。首版数值由 Rhythm 的活动规则集中维护，前端不复制报价。
- 六项技能为体能、探索、知识、表达、手作、亲和，当前经验与等级由服务器给出。
- 休息、外出、课程共用一个活动位置。外出和课程到期后保留待领取状态，玩家点击领取才结算并释放位置；读取和倒计时不会发奖。
- 活动中及待领取期间暂停照顾和开始其他活动，仍可领取每日补给、购买口粮、改名。没有取消活动或退款入口。
- 桌宠同步显示休息、外出、上课和待领取状态，外出/课程不会误显示睡眠图标。
- 本批活动只奖励经验、技能、心情及部分口粮，不产出宠物币。活动成长不占原照顾动作的每日十次成长额度。

## 接口与状态

沿用第一批目录和本人状态两个聚合 GET，不为每个地点、课程或技能单独请求。

| 资源 | 新增内容 |
| --- | --- |
| `GET /api/v3/pets/catalog` | `activityVersion`、`skills`、`places`、`courses` |
| `GET /api/v3/me/pet` | `pet.skills` 与外出/课程 `pet.activity` 快照 |
| `POST /api/v3/me/pet/activities` | `{petId,kind,entryId,activityVersion}` 开始活动 |
| `POST /api/v3/me/pet/activities/claim` | `{petId,activityId}` 领取指定活动成果 |

开始时冻结服务器目录中的费用、时长、成果，后续目录更新不改变这次活动。费用及成果的真实核验均在后端事务内，前端只做可用性提示。读取到的六项技能必须完整有效，字段缺失不能伪装成零经验。

前端新增操作沿用 `src/api/v3-pets.ts`、`src/stores/pets.ts` 的原键恢复、账号边界、跨标签失效和聚焦合并机制。不同活动的领取回执不能相互确认。普通令牌轮换保留未确认操作，退出/换号清理；后置 GET 失败只重读，不能重复开始活动或发奖。

本机每秒只更新倒计时，不轮询接口。时钟到点可以点击领取，是否已结束仍由服务器裁定；客户端不推算技能、经验、余额或奖励。

## 本地联调与验收

后端需先执行第二批活动表迁移并重新编译启动；前端与后端字段必须配套，不能仅更新前端后把旧服务的缺字段当空结果。

1. 在 `/pets` 领养后查看六项技能，选择广场散步；费用、时长与成果应先展示，点击后进入倒计时。
2. 进行中不能休息、唤醒或开始课程；刷新或另开标签仍为同一活动，离线等待后显示待领取。
3. 到期领取一次，核对经验、技能及口粮变化，活动位置恢复空闲；双击和两个标签同时领取不能重复奖励。
4. 选择学校课程，核对扣除宠物币及状态、对应技能成果；余额/状态不足时按钮不可用。
5. 弱网下开始或领取响应失败，核对入口恢复原操作；后置读取失败不能重复扣费/发奖。换号后不得留下前一账号宠物或草稿。
6. PC、390/320 窄屏检查活动卡片、消耗信息、技能区、待领取按钮和桌宠，不能横向溢出或遮挡关键操作。
