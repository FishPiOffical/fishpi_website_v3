# 聊天室发送时外观快照

## 已实现

主题继续保存在本机。个人气泡和头像框通过 `GET/PUT /api/v3/me/chat-appearance` 保存到 Rhythm，免费包为派派橘与摸鱼蓝。选择成功后 GET 当前配置确认；服务不可用时明确报错，不伪装成本机保存成功。

每条新消息在服务端实际写入时，把有效的 `{bubbleId, frameId, version}` 固化到现有 chat_room content JSON 的 appearance 字段。列表、详情和上下文随消息返回，不逐用户查询外观，不因后来换装而改写旧消息。普通、红包及其他共用消息保存原语的发布路径使用同一快照逻辑。

会员资格只在设置与新消息写入时检查。会员到期后的新消息回退默认，已发送消息保留历史会员外观。升级前无快照消息按默认样式展示，不能补造历史装扮。

## 前端与版本

`v3ChatAppearance` 管理本人配置和未确认原命令，正常令牌轮换保留、换号清除。写入未知结果保留原 ID 对及幂等键，成功后的读取失败只重读，不重写。

消息 `appearance` 经固定目录白名单投影，ChatBubble 按每条消息 data 属性渲染；经典/简约、悬浮聊天室、隐藏消息、上下文和首页简易聊天室共用快照。私信不在本次消息快照范围。未接入此协议的其他客户端不会自动渲染这些样式。

version=1 表示固定的样式目录版本，不是用户修改次数。以后改变既有图案需新增版本并保留旧版 CSS/解码；不能覆盖 v1 视觉后声称仍保留原历史外观。未知版本或不支持的 ID 显示默认；不接受自定义 CSS、HTML 或资源 URL。

## 升级顺序

1. 备份数据库，在 Rhythm 执行 `sql/20261107_api_v3_chat_appearance.sql`，按实际 jdbc.tablePrefix 调整表前缀。
2. 用 Java 25 在 IDEA 重建并重启 Rhythm；缺少新表会阻止新消息写入，不能先启动新代码。
3. 构建部署 website_v3。旧服务未升级时选择器会显示接口错误，不静默回退。

无需消息表 ALTER 或全量历史回填；当前偏好存在独立表，快照与消息同事务写入。此代码尚未部署，未执行生产迁移。
