# 聊天室个人外观同步建议（待实现）

## 当前状态

`appearance` store 只将 theme/bubble/frame 存入本机 `fp.appearance`；CSS 根据 html 的 data-bubble/data-frame 应用于整个消息列表。它是本机阅读外观，不是发送者外观。v3 聊天 author 白名单只包含 ID、用户名、昵称、头像，没有气泡/头像框配置。会员昵称 configJson 也不能作为普通用户外观存储。

派派橘与摸鱼蓝两套免费包已实现，权限由静态 pack.json 的 vip=false 决定；当前尚未跨用户同步。

## 建议的服务端协议

以下为设计建议，不是现有接口：

- `GET /api/v3/me/chat-appearance` 读取本人的 bubbleId、frameId 与 version。
- `PUT /api/v3/me/chat-appearance` 明确设置两个 ID，使用现有认证与幂等写约定；服务端验证已发布包白名单及当前 VIP 资格。免费包不要求 VIP。
- 用独立的用户外观配置保存，不能依赖 VIP 名单，也不能信任发消息请求里自行携带的样式。
- 在现有聊天详情、分页、上下文的 author DTO 中附带经过权限校验的 `appearance: { bubbleId, frameId, version }`。同一批消息可按作者 ID 在服务端去重读取，避免客户端逐消息查配置。
- 未配置、未知 ID、会员过期时返回有效默认样式。只传静态包 ID，不接受用户 CSS、HTML、脚本或任意资源 URL。

## 客户端渲染

保留主题为本机偏好；气泡与头像框按消息发送者应用到每个 `.fp-msg` 的 data 属性，而不是 html。包 CSS 同时支持本机预览和消息级选择器，逐步接通经典/简约、悬浮聊天室和隐藏消息，不能假称原站点客户端也会自动支持本项目样式。

修改后本人明确刷新当前外观。其他在线读者通过仅包含用户 ID/version 的失效事件批量重读当前消息/作者外观，沿用 v3 首帧票据及身份隔离，不向 WebSocket 推任意 CSS 或消息正文。已经存在的同作者消息推荐随当前外观更新，不固化每条消息的历史外观；如需历史装扮需另行定义快照与权限规则。

写成功后仅 GET 当前配置确认；未知结果保留原两个 ID 和幂等键，正常 token 轮换不丢命令，账号变化清理。更新会员权限后的读取和缓存也须重新验证，不能只在前端禁用 VIP 按钮。

实施需要 Rhythm 增加保存与公开投影，及 website_v3 的 API/命令、消息 DTO、消息级 CSS 与失效逻辑共同改造。当前提交未修改 Rhythm。
