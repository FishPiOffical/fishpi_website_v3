# 宠物测试工具补强与针对性复测

## 本轮范围

只修复八小时报告复盘中的前五项：真实 HTTP 漏测、陪伴旅程顺序、资产与分页断言、后端统计、正常截止分类。未修改宠物的生产代码、玩法参数、费用、日限、成长规则或界面；不部署、不推送。

| 复盘问题 | 修复与证据方式 |
| --- | --- |
| 真实接口未覆盖剩余课程/工作、制作及重新领养 | 新增 `focused.py`，新建四个本地普通账号，遍历十二课程、六工作、六地点、三条旅程、全部配方及重新领养；每次成功写入都用原键重放核对。 |
| 陪伴旅程先玩耍再喂食/饮水 | 长跑先喂食，水分自然下降后饮水，再玩耍，逐步检查进度；专项使用局部状态夹具，真实执行同样顺序与重复领奖拒绝。 |
| 奖励与拒绝操作断言不完整 | 领取核对经验、宠物币/日限、食物/材料、技能、职业熟练度与次数、心情；拒绝操作和成功重放均核对资产、成长、冷却、活动计时；跨日与自然衰减单独处理。 |
| 日志只读第一页 | 全页读取实际日志与活动历史，校验数量、排序、去重及活动 ID、冻结奖励、实际成果；成功命令与日志净增量、数据库钱包流水分别对账。 |
| 后端显示 PASS 0、正常到期被列为中断 | 读取结构化基线类、不变量、并发场景计数，正常结束独立列出；保留手动停止、异常、未完成核验的明确分类。 |

## 可复现命令

以下从 website_v3 根目录运行。工具专项只使用替身与本地快照，不登录、不写数据库。

```sh
node tools/pet-soak/report-test.mjs
python3 tools/pet-soak/assertions-test.py
python3 tools/pet-soak/focused-fixture-test.py
python3 tools/pet-soak/focused-lifecycle-test.py
python3 tools/pet-soak/focused-audit-test.py
npm run test:pets
```

真实 HTTP 专项需要两个仓库处于 `pet` 分支、本地 Rhythm 已在 `localhost:8081` 启动、`rhythm-dev-mysql` 运行，且保留本地专用账号模板 `.idea/rhythm-local/sso-fixtures.json`：

```sh
python3 tools/pet-soak/focused.py --rhythm /Users/ling/Documents/GitHub/rhythm
```

工具自动创建独立目录 `.temp/pet-soak/focused-<时间>-<随机标识>/`。凭据只写入权限为 600 的私有文件，不打印、不提交。全部账号共用每分钟三十次 HTTP 请求上限，拒绝代理及重定向，不请求生产；身份/限流或未知结果立即停止，未核验命令保留原内容和幂等键。与八小时运行器共用原子 `active.lock`，不得同时启动；按 Ctrl+C 受控停止，一小时保护截止也只记未完成。

完整成功后可执行一次独立只读数据库对账，按 HTTP 成功回执而非预设总数核验记录，结果只创建一次，不覆盖已有审计文件：

```sh
python3 tools/pet-soak/focused_audit.py --directory .temp/pet-soak/<本轮目录名>
```

后端回归保持原有隔离 SQLite 服务测试：

```sh

node tools/experiments/api-v3-pets-soak-cycle.mjs \
```

## 夹具与验收边界

- 专项账号领养后单独增加 9900 宠物币、六项技能各 20 经验；这些是明确的测试前置，不计为业务奖励。最终余额必须等于真实账本加该偏移。
- 为检查活动全目录，恢复该账号的体力等状态，并仅平移当前活动的开始/结束时间，保留原时长、费用、奖励快照。服务器时钟、日限和其它账号不变。
- 所有领取、制作、旅程与重新领养通过当前真实 HTTP 接口完成；无法由此宣称二十四项活动都自然等待过完整时长。
- 每个数据库夹具操作校验本轮新建账号及宠物归属，在用户行锁事务内提交，固定已验证的本机 Docker Unix socket。不能复用历史八小时账号补写覆盖率。
- 未改变 Java、公开路由、鉴权、验证码、CDN 或静态资源；无需服务重启、生产构建或修改反漏扫指纹。没有以该专项冒充真机、浏览器长时性能或全部未知缺陷验收。
- 人工复核：在本地 `/pets` 检查日常照顾、旅程奖励、日志翻页和换宠确认。自动化通过仅表示上述场景通过；宠物玩法节奏及实际设备体验仍需人工验收。
