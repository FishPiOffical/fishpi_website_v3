# main 仅保留 v3

用户要求先备份当前代码，再从 main 移除 v1 支持。本地 `v1_v3` 分支固定在 `ce9e4dde9dc8e9156819204494e81161a5ec9d84`，包含此前双版本适配与最近两次首页/操作按钮 UI 调整。未推送远端。

main 移除旧 apiKey 认证、全部 v1 适配器/状态/组件/恢复入口、版本设置、模式 Cookie/环境变量分派及旧协议测试。现有 v3 组件直接接线，保留新 UI、内存 Bearer、HttpOnly 刷新 Cookie、未知命令原键恢复与身份隔离。旧脚本登录及 API Key 缓存工具不再提供，sitemap 改读 v3 文章列表。

旧 `fp.apiMode=v1` Cookie 或 `VITE_API_MODE`/旧目标环境变量不能启用旧协议。Node 和 SPA 开发服务的共同边界拒绝旧 `/api/` 资源并返回 410 JSON；生产 nginx 示例也限定 `/api/v3/`。仅保留 v3 需要的验证码、风险验证、勋章图及明确导航的游戏资源代理，不保留旧认证/内容写入代理。

需求反馈仍独立运行：前端只发内存 Bearer，后端只通过固定 `/api/v3/me` 核验，旧专用 key 请求不能通过认证。`/feedback-api/v1` 与 RhyPic `/api/v1/files` 是各自服务的版本，不是网站 v1，继续保留。反馈数据库未删除或重建。

## 启动与分支配置

网站仅使用 `VITE_API_TARGET` 指向实际支持 v3 的 Rhythm。本地本次启动目标为 `http://localhost:8081`，当前未检测到该端口监听；因此依赖 Rhythm 的内容不能作为生产联调已通过，站点不会回退现网 v1。网站 `127.0.0.1:5173` 和反馈 `127.0.0.1:5174` 保持运行，反馈公开列表/健康检查正常。反馈 `RHYTHM_ORIGIN` 需同样配置为受信任 v3 上游，未配置管理员白名单。

切换回备份代码可用 `git switch v1_v3`，但切换前应处理工作区修改并重启服务。Git 不包含忽略的 `.env.development`、凭据或数据库；双模式分支须按其 `.env.example` 配置 `VITE_API_MODE`、`VITE_API_V1_TARGET` 和 `VITE_API_V3_TARGET`，不能假设分支切换会恢复本机环境文件。
