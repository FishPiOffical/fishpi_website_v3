# 宠物家园第五批：进阶课程、成长旅程与重新领养

在两个仓库的 `pet` 分支继续开发，使用现有静态形象。本批只做本地联调与提交，不推送、不部署，动画仍放在最后。

## 学校

六项技能各增加一门进阶课，仍与外出、工作、休息共用一个活动位置。对应技能达到 20 经验后开放：30 分钟，10 宠物币，消耗精力 14、饱食 5、水分 7；完成后手动领取 30 宠物经验、20 对应技能经验和 5 心情。已开始的活动使用出发时冻结的数值，不随目录变化重算。

学校沿用原分类入口，分为入门与进阶，不新增无内容入口。未解锁课程显示缺少的技能经验。

## 成长旅程

三条事件链独立推进，每条包含三个顺序目标。只计算本版上线后的真实成功操作，不回填历史，不接受客户端直接增加进度。一次操作对每条链最多推进一步；先完成后面的活动不会预先记录下一步。

| 旅程 | 按顺序完成 | 整链奖励 |
| --- | --- | --- |
| 陪伴的日常 | 喂食 → 饮水 → 玩耍 | 基础口粮 ×2 |
| 荷塘见闻 | 自然观察课领取 → 荷塘采集领取 → 自然研究课领取 | 鲜果 ×2、芦苇 ×2 |
| 第一次小小工作 | 任意课程领取 → 任意见习工作领取 → 任意进阶课领取 | 清泉饮 ×2、海贝 ×2 |

旅程进度随聚合状态一起返回，不新增轮询。三步全部完成后，宠物空闲时可以手动领取一次整链奖励。奖励只发物品，不额外发币。进度、完成时间和领奖事实属于账号，重新领养不会清除；未确认操作仍用原键恢复。

## 重新领养

价格按用户确认设为 **512 宠物币一次**，不使用站点积分。入口位于家园的伙伴设置，打开弹窗后选择四种宠物之一、填写名字，并明确确认成长重置。原宠物正在休息、活动中或活动待领取时，不能更换。

- 新宠物使用新 ID，重置等级、经验、亲密度、六项技能与六项工作熟练度。
- 保留账号钱包余额（扣除本次费用）、背包、永久收藏、旅程进度与奖励领取记录。
- 不再次发放首次领养的币和口粮，不重置当天补给、工作产币额度、日常成长额度与互动冷却。
- 旧宠物的资料由服务端归档；原活动、技能和工作记录不删除，统一日志仍可查看旧记录。
- 旧页面携带旧宠物 ID 的新命令不能作用于新宠物。已成功操作的原键只返回历史回执，前端必须重读当前状态。

## 接口与恢复

目录 `version: 3`、`activityVersion: 4`，新增 `stories` 和 `readoptionRules`；聚合状态新增 `stories`。客户端不把缺失的字段伪装为空进度。

- `POST /api/v3/me/pet/stories/claim`：当前 `petId`、`storyId`、`catalogVersion`。
- `POST /api/v3/me/pet/readoption`：当前 `petId`、目标 `speciesId`、`name`、`catalogVersion`、`resetAccepted: true`。
- 统一日志新增 `story` 和 `readoption` 分类，仍只在展开时读取。

两种写入共用串行命令、账号边界及幂等恢复。重新领养回执同时校验新 `petId` 和 `previousPetId`；回执不直接覆盖当前宠物、余额或背包。成功后的 GET 失败只允许重读，不再次消费。普通令牌轮换保留草稿，退出、换号、同账号重新认证清除私人状态并拒绝迟到响应。

## 本地人工验收

先执行配套 Rhythm 第五批迁移并重新编译/启动，再访问 `http://127.0.0.1:5173/pets`，使用本地临时账号：

1. 检查学校分组；技能低于 20 时进阶课不可开始，达到 20 后可开始，未到期不能领取，到期只发一次成果。
2. 按喂食、饮水、玩耍顺序完成照顾旅程；提前饮水不跳过喂食，刷新不推进，完成后领取奖励，重复点击不重复发奖。
3. 通过课程、探索和兼职推进其余旅程，核对技能、进度、奖励与活动日志；已领取的旅程保持完成。
4. 活动中、待领取或余额不足时重新领养不可用；空闲且余额足够时勾选确认更换，检查只扣 512 币，成长重置，钱包/背包/收藏/旅程/额度保留，日志仍含旧记录。
5. 断网后恢复原操作、成功后 GET 失败、换号、两标签页同时操作时，不能重复扣费、领奖或将旧宠物数据写入新宠物。
6. PC、390px 和 320px 窄屏检查旅程步骤、弹窗滚动、键盘焦点、错误提示和日志分类。

人工测试结果尚待用户反馈，本地提交不代表已完成验收或可以发布。
