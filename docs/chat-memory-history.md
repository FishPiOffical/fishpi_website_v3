# 聊天室内存历史与连接使用权

首页、聊天室页和展示聊天室的悬浮窗通过同一个 chat store 申请连接使用权。最后一个入口离开后延迟 500ms 释放网络连接，给 SPA 路由挂载交接留出时间；释放连接不删除同账号历史。一个入口关闭不能断开其他入口的连接。

再次进入先展示 Pinia 内存中的消息，后台恢复订阅并核对最新消息窗口。连接仍被其他入口使用时，不再次订阅或重读历史。断线同步和补读不会先清空已有内容；成功后以服务端最新窗口替换，并保留读取期间收到的更新和删除保护。补读失败保留旧窗口，401/403 则清除授权数据。此实现不声称保存断线期间的全部分页：最新窗口之外仍通过“更早记录”读取。

退出、换号和 store 销毁清空消息；正常令牌轮换保留当前可见内容并重绑授权连接。缓存不写入本地存储，不进入 SSR，整页刷新不保留。首页与浮窗的 UI 标记不再承担连接释放判断。

验证：
- `node tools/chat-connection-owners-test.mjs`：重复申请、路由交接、多个入口、最后释放、销毁计时器。
- `node tools/v3-chat-timeline-test.mjs`：离页保留、迟到响应隔离、重连与同步不闪空、失败保留、退出/换号清空；既有实时快照、删除和权限专项继续通过。
- `npm run build`：类型检查、客户端及 SSR 构建通过。
- 本地 Chrome 无头浏览器验证游客 `/cr` 首屏挂载及真实浏览器定时器下的连接使用权交接。连接和消息测试使用本地夹具；尚未用两个真实账号进行长时间网络中断人工验收。

本地预览运行在 5184；原有 5173 服务未改动。本轮不部署、不推送。
