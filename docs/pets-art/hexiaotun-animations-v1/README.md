## 制作与复现

- 新绘制九项均使用内置 imagegen，以已确认角色和吃叶子源帧为参考；完整实际提示词及修订来源保存在 [sources](sources/) 各动作的 Markdown 中。
- 每段使用 **16 个独立绘制帧**，通过停留时长形成动作节奏，再输出到 24fps 视频时间轴。24fps 不代表每秒 24 张新绘制帧，没有光流或自动过渡补帧，也没有拆分身体做骨骼变形。
- 导出仅将 4×4 连续帧分离、等比例缩放并对齐落脚位置。同一动作全程使用同一缩放比例，避免逐帧拉伸；锚点从实体区域读取，淡透明背景不参与定位，源图透明通道不被重绘。
- 保留首次认可的吃叶子视频，SHA-256：`1abf196eccbdc07919668b92f321e7d4aad2b412094c5e1ec63011ccf149af31`。它与之前 `feeding-corrected-v4/feeding-256.webm` 字节一致，未使用被否定的补帧版。
- 本轮针对性修正了上课的淡背景残留与帧对齐、睡觉和待机的姿态区别，以及喝水的倾杯动作。

在仓库根目录运行，需安装含 `libvpx-vp9` / `libwebp` 的 FFmpeg 和 Chrome：

```sh
PET_FFMPEG=/absolute/path/to/ffmpeg node tools/pet-animation-export.mjs
node tools/pet-animation-preview.mjs
node tools/pet-animation-verify.mjs
```

导出脚本不重新制作已认可的 `eat.webm`。可在第一条命令末尾传 `sleep study` 等动作 ID，只重新导出指定动作。`PET_CHROME` 可指定 Chrome 路径；测试会启动自己的临时只读服务和浏览器实例，结束后关闭，不借用登录浏览器。

## 验证与边界

- Chrome/157.0.8103.51 实测十段均为 256 × 256，时长匹配、能跨结尾循环，无媒体错误；逐段在解码后的 Canvas 中验证透明像素及实体像素，而非只看容器元数据。
- 检查深底、浅底、单项和全部对比，确认上课不再显示淡矩形底；移动端 390px 无横向溢出，128px 显示尺寸正确，十个动作均可选择。
- 检查四肢和帽子，没有发现之前的额外手爪问题。源帧重绘仍有轻微轮廓差异，首尾是相近姿势，并非逐像素无缝。本版需用户看过实际动作后再确定最终素材，不把自动播放检查当作艺术验收。
- [validation.json](validation.json) 保存本次独立浏览器验证结果；截图位于 `.temp/hexiaotun-animations-v1/qa/`。
- 仅修改美术、离线预览及制作工具，执行了三个工具的语法检查、实际编码与浏览器验证，未运行应用构建；没有更改 `src/`、Rhythm、账号数据或原 `pet` 工作区。
- 本次未验证其他浏览器与实际移动设备。未来接入保留现有静态图回退和减少动态效果偏好，业务未知结果不能播放成功动画；仍从当前服务器状态决定长期动作。
