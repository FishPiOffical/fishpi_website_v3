# 聊天室复读叠卡

连续的普通文字／Unicode Emoji 消息按原始正文精确分组，不追加读取请求；进出场和红包领取通知独立保留且不打断分组；其他通知、特殊卡片、引用及不支持的富文本会断开分组。图片与图文的匹配规则见下文。正文由现有 V3 消息快照透传到 ChatLine，不修改后端或历史消息。

经典、简约和悬浮聊天室共用 ChatRepeatList。最新消息完整显示在最前层，整组方向跟随第一条消息的发送者，后续自己或他人复读不会换边。之前最近六条作为后层，只显示 20×20 头像与 24px 高的气泡切片（保留正文/图片片段），每层间距 28px，不再显示昵称、宠物、时间或操作栏；更多消息展示总数。展开后仍沿组首方向，保留原消息的身份、外观、小尾巴和独立操作，+1 复用原有复读流程。精简模式不显示后层外观包。首页预览和隐藏会话暂不分组。

本地验证：
- `node tools/chat-repeat-test.mjs`：连续分组、通知边界、正文差异、特殊内容排除及原消息保留。
- `npm run build`：类型检查、客户端与服务端构建通过。
- Chrome 组件夹具：1000／560／390px 无横向溢出；展开、收起、计数更新、经典反序与清屏通过。夹具用模拟正文及操作按钮，不发真实消息；尚未用真实账号验证复读发送、撤回后的分组和长历史滚动。

本次只提供本地预览，不部署。

## 图片复读分组

连续图片按原图地址匹配，RhyPic 已知 `/w/尺寸` 路径和 `imageView2` 缩放参数归一到原图；其他参数、签名以及第三方地址保持区别。图文混排按清洗后的正文结构比较文字、空白、文字格式和图片顺序，图片 alt/显示尺寸不作为内容差异。链接、引用及特殊卡片不参与此次扩展；原消息不变，展开后仍使用各自原消息操作。

经典、简约和悬浮聊天室共用分组组件，不新增网络读取。`node tools/chat-repeat-test.mjs` 覆盖同图不同缩放、多图顺序、不同文字、签名和第三方参数、非法图片地址及通知边界；类型检查及完整构建通过。Chrome 本地夹具使用真实 ChatRepeatList 和实际外观 CSS，验证桌面/390px/560px、图片叠层头像可见、展开、实时计数及倒序；未在生产发送测试消息。

对照旧站 chat-room.js 的堆叠逻辑，新复读必须覆盖在前层，头像、时间、外观和 +1 目标均使用最新消息。分组 key 仍固定最早成员以保留展开状态。Chrome 组件夹具验证图片最新成员位于前层、追加后立即更新、经典倒序、展开和窄屏头像无遮挡；完整构建通过。


## 2026-11-14 收紧折叠层与固定方向

`ChatBubble.alignSelf` 仅控制视觉方向，`self` 仍为真实作者身份，点击名字 @、宠物归属、撤回和举报不以组首作者推断。经典、简约和悬浮聊天室均透传复读组方向；单条消息不传覆盖值，继续使用原有左右排列。后层复用每条消息的外观颜色、20px 头像及文字/图片预览，不增加消息/用户查询；精简和图片模糊设置继续生效。

分组、图片匹配及进出场/领取通知跨越行为不变，+1 仍以最新一条原消息为操作目标。

本地验证：`node tools/chat-repeat-test.mjs`、`npx vue-tsc -b` 和 `npm run build` 通过。`tools/chat-repeat-browser-test.mjs` 使用实际 ChatRepeatList、ChatBubble、ChatQuoteCard 与外观 CSS，覆盖首条双方身份、追加/倒序/展开、六层上限、320/390/560/1000px、图片、通知跨越、精简/模糊和 +1 防连击；实际 @ 行为确认视觉方向不会改变作者身份。引用定位专项 `tools/chat-context-browser-test.mjs` 也通过。本轮使用隔离浏览器夹具，未向线上发送消息，未部署。
