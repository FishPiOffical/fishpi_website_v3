# 摸鱼派宠物乱斗开发设计

2026-11-16 复核版。当前为开发方案，生产战斗引擎与价格待实现验证。原作参考见[规则调研](pet-brawl-research.md)，价格和产速见[积分方案](pet-brawl-points.md)，原型测算见[复核记录](pet-brawl/README.md)。

## 已确认目标与本轮调整

当前宠物 Lv.10 起可以参加，乱斗付费使用站点积分，战斗养成消费获得实战提升，人均消费目标为 10,000–30,000 积分。现有等级每 100 经验升一级，Lv.10 对应 900 经验，实施时继续调用服务端等级规则。[现有养成规则](pets-phase-one.md)

本轮建议将主要 PvP 调整为实装对战，从首次 PvP 上线起使用装备与成长快照。统一基础值用于开发模拟和 NPC 陪练，报名集中在一个匹配入口。90 天继续作为消费观察的暂定窗口，永久资产跨周期保留。此前助手提出的每赛季 30,000 积分消费硬上限取消，战力由装备等级、出战槽位和效果上限约束。

| 发现的问题 | 调整 |
| --- | --- |
| 木勺持续加伤，护腕只挡两次，技能收益不等 | 首轮按等量收益比较配装，再逐个增加不同触发条件 |
| 交替先手让终结回合奇偶影响胜负 | 每回合独立随机先手，服务端预生成随机序列 |
| HP 和攻击同时加 5% 就造成明显压制 | 强化、镶嵌和助战进入同一成长预算，逐层测试叠加 |
| 积分强化早于实装 PvP 开放 | 先做实装对战与装备模型，再接消费 |
| 23,000、30,000 消费示例缺少具体购买路线 | 建立首套 18,000 积分的完整成长账本 |
| 同等级严格分组可能无足够对手 | 在相近等级优先基础上受控扩展，保留真实无对手状态 |
| 双方确认缺邀请模型，单账号事务无法直接拼 PvP | 首版持续报名异步匹配，采用专用双账号事务，点名约战后置 |

## 基础玩法

- 家园的「乱斗」包含陪练、闯关、对战、装备和战报。Lv.1–9 显示解锁进度，四物种首版共用基础属性，个性由立绘、招式和演出呈现。
- NPC 陪练可反复测试配装，使用账号级限流。服务器生成战报，浏览器可暂停、跳过和重播，结果在播放前已经确定。
- NPC 闯关每天前三场完成对局分别发 5、5、10 单位历练材料，每账号每天共 20。胜败均给参与材料，胜利推进关卡和首通成就。重复已解锁关卡可以完成每日材料获取，其余挑战仍可免费练习。
- 实装 PvP 默认关闭报名，用户主动开启「接受匹配」后可与其他报名宠物异步对战。开战冻结双方宠物、装备、属性和规则版本。后续强化在下一场生效，历史对局使用原快照。
- 首测每账号每天主动匹配 3 次、被匹配最多 6 次，同一对账号每天只计一局，双向合并。初期 PvP 记录胜负与战报，成长材料由 NPC 提供。奖励开放前测算收益和互刷。
- 战斗生命只用于本局。外出、学校、工作与休息中的宠物也可异步参战，乱斗仅读当前宠物 ID 和等级。养成活动领取不成为开战前置操作。
- 关闭报名退出候选，已提交对局保留。重新领养后旧报名失效，账号资产、材料、首通和日额度保留，新宠到 Lv.10 后重新装备并报名。

## 战斗原型与数值验收

首版出战一件武器和一个招式，后续扩展一颗魂珠、一枚符石和一位助战。其他已持有物品用于更换打法，只有当前出战配置贡献属性。

| 项目 | 候选规则 |
| --- | --- |
| 生命与回合 | 基础 100 HP，每回合双方各行动一次，最多 12 回合。HP 到 0 即结束。到上限比较剩余生命比例，相同判平，使用整数交叉相乘比较。 |
| 先手 | 每回合独立抽取 50% 先手，由服务端随机种子确定。 |
| 普攻 | 基础伤害 9，整数波动 −2 至 +2，8% 暴击，倍率 1.5。暴击只作用于普攻部分。 |
| 小木勺 | 前 8 次攻击每次加伤 1，合计最多 8。 |
| 软垫护腕 | 前两次受击各减伤 4，合计最多 8。 |
| 折纸扇 | 第 3、6 回合攻击各加伤 4，合计最多 8。 |
| 拍水花 | 第 4 回合攻击额外伤害 8。 |
| 卷成一团 | 第 4 回合结束后获得 8 点护盾，抵扣下一次受击，余量随这次受击结束清除。 |
| 深呼吸 | 第 4 回合行动前回复 8 HP，最多回到最大生命。 |
| 顺序 | 行动前回复 → 普攻波动与暴击 → 固定武器/招式加成 → 固定减伤与护盾 → 最低伤害 1 → 胜负判断。 |

引入细小成长增益时，生产内部用百分之一 HP 的定点整数，统一舍入规则。原型整数伤害测试只验证原型精度，换精度后重新跑配装矩阵。

本轮对旧规则和候选规则各计算 648,000 局，覆盖 9×9 有序配装、4,000 个种子样本及交换随机序列和先手的成对对局。得分率为胜局加半个平局的比例。

| 指标 | 旧规则 | 候选规则 |
| --- | --- | --- |
| 各配装对等权对手池的平均得分率范围 | 37.929%–64.233% | 48.589%–50.736% |
| 镜像配装中首回合先手者实际胜率范围 | 40.975%–64.150% | 48.975%–50.700% |

候选版策略差异仍偏弱，后续增加克制或触发条件时须再跑全矩阵。同时结算、双 KO 判平的试验产生约 37.88% 平局，首版选择逐个行动结算。成长敏感性测试中，HP 和基础攻击同时加 5% 时，同配装进阶方平均得分率约 82.6%，同时加 10% 时约 97.1%。测试脚本、结果与精度差异见[复核记录](pet-brawl/README.md)。

成长效果共用规则函数。强化、神器、魂珠、符石和助战都计入同一效果预算，各项目增益通过模拟后确定。原稿完整成长只增加 5–15 个胜率百分点的统一目标撤下。候选验收包含以下三组。

1. 同进度的基础九套配装，等权平均得分率目标 45%–55%，首回合先手者条件胜率 47%–53%，总体平局率低于 5%。逐个对位矩阵另列，检查持续压制全部打法的组合。
2. 同等级、固定对手集和成对种子，逐级记录升级前后伤害、有效减伤、治疗和得分率。每档强化有可观察的数值提升，积分和免费材料取得相同物品使用相同效果函数。
3. 基础、中期、完整成长交叉对局，完整成长对对应基础配装暂以 65%–80% 得分率作为调参窗口，具体随原型复核。超出时复查属性叠加和随机方差。使用多个独立种子批次与置信区间，边界附近增加样本，同种子镜像按成对样本处理。

## 匹配与隐私

优先相近等级与对战成绩，再用有界战力差排除悬殊对局。先测等级差 ±2，再扩大到 ±5，战力估值比上限暂取 1.3，随成长模型和活跃人数复核。战力估值按实际出战快照计算，并校准其与模拟结果的相关性。冷启动使用等级与装备估值，已有战绩后加入成绩区间。升级后仍允许遇到合理范围内原先较难的对手。

候选查询有数量和时间预算，无合适对手时明确反馈并引导陪练。事务中复核所有筛选条件和装备版本，换装视为合法玩法。初期对手摘要仅向符合资格的报名参战者展示，完整战报只供双方查看。历史宠物昵称也应用现有违规昵称审核替代名。

## 技术与数据

### Rhythm

- 纯引擎输入双方不可变快照、种子和规则版本，输出有界事件与结果。保存实际事件以重播，目录版本、价格版本和战斗规则版本独立记录并保留可复现数据。
- 用专用双账号根事务。现有宠物写服务先锁本人且禁止嵌套事务，实施时核对鉴权客户端锁、用户锁、宠物/装备/日报锁与幂等行的完整顺序，对照积分转账和换宠的锁顺序。
- 候选在事务外只读筛选，按核对后的全局顺序锁双方，再校验资格、报名、当前宠物、装备版本、配对与额度。失效候选只做有界重新选择。战报、双方次数、配对记录及回执同事务提交。业务日期使用根事务开始时的服务端北京时间并冻结入回执，跨午夜重试先恢复原结果。
- 普通 PvP 使用双方业务事务。积分购买和付费 NPC 参照外观商城，在根事务前取得积分转账锁，购买或成长一次提交扣款、双边流水索引、材料、资产和订单，付费开战再把本局战报纳入同一事务。外部素材与其他网络请求在事务外处理。验证反向对战、强化、转账和换宠并发。
- 风控显式注册报价、开战、购买和强化等操作。鉴权后优先恢复已确认命令，首次提交才走当前风险和业务检查。暂无对手、配额用完与改价按业务拒绝统计。
- 管理入口放在既有 backend 项目的宠物/乱斗管理，由 Rhythm 提供独立管理员授权接口。先做战报、订单和风险日志只读查询，商品采用版本化目录和独立开关。编辑目录在消费闭环验收后接入，已有 /admin 宠物日志沿用其现有范围。

| 数据 | 主要约束 |
| --- | --- |
| 报名与配置 | ownerId、当前 petId、报名状态、loadoutRevision、出战配置。开战始终核对真实当前宠物。 |
| 账号资产 | ownerId、物品 ID、等级/数量和 revision。乱斗独立目录，当前宠物 API 的封闭枚举须显式扩展或用独立适配。 |
| 日额度、首通 | ownerId+北京时间日期+模式，首通 ownerId+稳定 rewardId。数值改版只变规则版本，新一期奖励显式发新 rewardId。换宠保留。 |
| 配对 | 日期+模式+排序后的双方 ownerId 唯一，双方发起也只计一局。 |
| 战报 | 双方账号、历史 petId/物种、配置快照、规则、事件和结果。双方时间游标索引，独立授权与容量预算。 |
| 订单、成长流水 | ownerId+orderId 唯一，命令摘要、报价/配方版本、资产版本、积分与材料净变化、终态及关联战报。 |

### 接口与客户端

| 拟新增 V3 资源 | 用途 |
| --- | --- |
| GET /api/v3/me/pet/brawl | 本人资格、报名、额度、配装、内容版本 |
| PUT /api/v3/me/pet/brawl/profile | 保存报名与配置，提交真实 petId、期望版本及幂等键 |
| POST /api/v3/me/pet/brawl/matches | 免费 NPC 或 PvP 开战，付费开战通过订单确认 |
| GET /api/v3/me/pet/brawl/matches[/{id}] | 本人战报列表与当前权限下的详情 |
| GET /api/v3/me/pet/brawl/inventory | 当前资产、材料、权益与可用升级 |
| POST /api/v3/me/pet/brawl/orders | 免费创建报价订单，冻结选择、材料、费用及有效期 |
| POST /api/v3/me/pet/brawl/orders/{id}/confirm | 本人明确确认订单，原子扣款/材料并提交结果 |
| GET /api/v3/me/pet/brawl/orders[/{id}] | 本人订单分页与结果，刷新后核对消费 |

沿用第一方本人权限，具体 scopes 以现有鉴权核对。新增乱斗适配器和 store，进入玩法后才读取。SPA 内保留原命令，普通令牌轮换保留，换号清私有状态，拒绝迟到回包。刷新后可通过订单核对上次结果，成功后 GET 失败只重读。

SSR 只输出页面骨架，复用 FpDialog、认证和风险验证交互。家园、桌宠与聊天室只接导航或已有摘要。活动日志后续合并乱斗摘要时显式增加记录类型，避免当前枚举解码失败。

## 开发批次

| 批次 | 交付 | 完成条件 |
| --- | --- | --- |
| 0. 模型 | 引擎、成长预算、价格和材料模拟，事务锁序审查 | 基础/成长矩阵通过候选阈值，给出每档增益与完整消费路径。 |
| 1. 免费闭环 | 门槛、陪练、NPC 材料、装备强化模型和战报 | 隔离库验证免费养成、奖励去重、恢复与换宠，PC/窄屏完整可玩。 |
| 2. 实装 PvP | 自愿报名、单匹配池、快照、额度与日志 | 强化在主要 PvP 生效，覆盖反向并发、换装/换宠和候选不足。 |
| 3. 积分闭环 | 报价订单、材料抵扣、五档武器成长、流水和恢复 | 扣款、材料和成长可对账，重复确认与整页刷新只结算一次。 |
| 4. 进阶配装 | 神器、双槽、魂珠和符石 | 每增加一个系统重跑叠加矩阵，验证效果预算。 |
| 5. 长期玩法 | 单助战、实装榜、固定礼包，按活跃度评估约战与赛季 | 经济与互刷验收，永久资产跨季保留，完整目录评估人均目标。 |
| 6. 演出 | 四物种出招、受击、胜负和外观 | 轻量素材、静态回退、手机端、省流和减少动态验证。 |

点名约战另需邀请 ID、双方宠物/装备版本、接受/取消/过期状态和唯一对局约束。多人混战另定规则。每批先隔离本地联调，按风险运行事务/接口专项、前端类型检查和构建，并进行浏览器验收。Rhythm 新注释用中文，保留原注释及无关格式。
