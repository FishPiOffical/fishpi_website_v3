# 角色权限与身份展示

## 原因与旧站规则

V3 的聊天室撤回入口与写接口曾同时限制为消息作者，导致旧站可管理他人消息的角色失去入口。修订历史组件仍存在，但文章和评论页面已不再挂载它；用户菜单也缺少经典后台入口。

本次对照 Rhythm 的 `DataModelService.hasPermission`、角色权限目录与经典模板，沿用原有权限：

| 操作 | 原规则与本次处理 |
| --- | --- |
| 撤回他人普通聊天消息 | 管理员、OP、纪律委员属于旧站 level 3，管理撤回不扣积分；红包仍不可撤回 |
| 撤回本人普通聊天消息 | 普通用户仍可撤回自己的消息，费用由服务端按原规则计算 |
| 文章、评论修订历史 | 分别按 `commonViewArticleHistory`、`commonViewCommentHistory` 角色授权显示，不使用 `isAdmin` 代替 |
| 管理后台入口 | 按 `menuAdmin` 权限显示，打开 Rhythm `/admin`，目标页面再验证经典会话 |
| 强制编辑、删除及用户管理 | 保留经典后台各项权限；不扩大用户站的本人编辑、删除 API |
| 话题、弹幕及禁言 | 未改变原业务权限或收费规则；管理角色并不意味着话题、弹幕免费 |

## 私有能力与公共角色分离

第一方 `/api/v3/me` 返回 `capabilities.chatRevokeOthers`、`viewArticleHistory`、`viewCommentHistory`、`canAccessAdmin`。前端只认可严格布尔值 `true`，不根据角色显示名、角色徽牌或 `isAdmin` 推导这些能力。第三方客户端不会因本次修改获得管理撤回权限。

能力只决定入口可见性，不能替代服务端授权。撤回写接口使用认证中间件提供的客户端身份，事务内重新读取当前用户并复核原管理角色。已有原命令、幂等键及结果未知恢复流程保持不变。

历史面板在权限回收、换号或退出后关闭并拒绝迟到结果。同账号令牌轮换不清除未确认撤回。后台链接只包含服务地址，不拼接 Bearer、用户 ID 或其他凭据；SSR 不显示该链接。

公开 `/users/:name` 的 `userRoleId` 仅供 `UserRoleBadge` 选择视觉样式，公开 SSR 与缓存白名单不包含 `capabilities`。资料卡后台成功读取会同步新的角色名称和 ID，避免其余资料缓存有效时仍显示旧角色。

## 身份样式

个人主页与悬浮卡片使用同一组件，保留各自原有布局。徽牌使用内联 SVG，无新增图床请求：

| 身份 | 颜色 | 图标 |
| --- | --- | --- |
| 管理员 | 石墨灰 | 盾牌 |
| OP | 橙色 | 工具 |
| 纪律委员 | 蓝色 | 盾牌勾选 |
| 超级会员 | 琥珀色 | 皇冠 |
| 成员 | 绿色 | 用户 |
| 新手 | 青灰色 | 幼苗 |
| 游客 / 自定义身份 | 灰色 / 中性色 | 用户 / 纯文字 |

深浅色主题均使用淡底色与可读文字；长名称省略并保留完整悬浮提示。旧服务器缺少 ID 时兼容角色名称，仅用于展示，不赋予权限。

## 验证与发布边界

- `node tools/v3-chat-revoke-test.mjs`：撤回入口、管理确认、权限撤销、未知命令恢复及换号隔离。
- `node tools/v3-revisions-test.mjs`：对应历史能力、点击后读取、普通令牌轮换、迟到响应及收回权限。
- `node tools/user-role-badge-test.mjs`：角色展示、管理链接挂载与严格布尔权限、公开资料缓存更新。
- `node tools/v3-user-card-test.mjs`、`node tools/v3-ssr-payload-test.mjs`：公开角色白名单与能力隔离。
- `tools/user-hover-card-browser-test.mjs`：隔离浏览器验证长名、背景、窄屏与深浅色身份徽牌。
- 评论和长篇专项通过；补齐此前缺少的真实组件依赖映射，并把过期的屏蔽提示断言改为检查独立系统提示与正文隔离。
- 完整类型检查、客户端与 SSR 构建。

隔离浏览器还验证了撤回组件、真实撤回 store、历史组件、评论与长篇：普通账号零管理请求，授予能力后挂载仍不查询历史，点击后才查询；撤权清理及迟到结果隔离、确认期间撤权不提交、合法确认只向夹具提交一次。没有向外部站点发送这些操作。

额外巡检的 `v3-member-page-test.mjs` 第 7 项旧断言在改前 HEAD 同样失败，本轮未改变该个人主页测试覆盖的业务；因此本记录不代表全仓库测试全部通过。

本次浏览器使用本地隔离数据，不向线上发送撤回、举报或资料修改。前后端分别本地提交，不部署、不推送。必须配套更新并重启 Rhythm 后，前端才能取得新增能力；Java 完整应用及真实账号管理操作仍需人工验收。

人工验收：管理员、OP、纪律委员分别撤回测试环境他人普通消息；普通成员不能撤回他人、红包不可撤；按实际角色权限检查历史入口与后台入口；退出或换号后旧入口消失；在个人主页和悬浮卡片核对角色颜色及无背景、深浅色效果。
