# 宠物家园第七批：家园交互与成长引导

本批只调整 website_v3 的家园交互，不修改宠物业务规则、费用、成长和奖励，不制作新动画。Rhythm 没有变更，不需要迁移。

## 家园布局

原来的连续长页面分为六个区域：日常照顾、外出与学习、成长旅程、家园小铺、手作与收藏、活动记录。默认显示日常照顾，桌面导航一行展示，窄屏分为两行。窄屏宠物形象与名字并排，保留成长进度，减少到达照顾按钮前的滚动距离。

导航上方呈现当前已有的真实状态：

- 伙伴近况：正在进行的活动、休息或待领取成果，点击定位到对应区域。
- 每日补给：只在未领取时展示，点击定位到补给按钮，不自动领取。
- 成长旅程：优先显示待领取奖励，其次显示进行中旅程的下一步；内容取当前目录与进度。全部完成后不编造任务。

保留各区域原有功能与确认流程。切换采用 `v-show` 保留子组件，购买数量、活动分类、改名草稿和未确认操作不会因切换消失。身份或宠物 ID 变化时回到日常照顾，普通令牌轮换保留当前区域。

## 材料来源

尚未制作且材料不足的配方显示来源入口。只使用当前目录明确声明的探索材料奖励和可出售物品，不根据描述猜测掉落，不另外查询接口。

点击探索地点切换到外出分类并定位标题；点击家园小铺切到材料分类并定位物品。开始活动、购买和制作仍由用户明确操作。目标已从目录移除时回到当前区域，不能自动补查或执行旧目标。

## 请求与状态保护

- 分区和来源导航不新增 GET，不触发写请求。近况与旅程复用已有聚合状态。
- 活动记录仅在显式进入时打开；离开分区、换号、换宠和卸载时关闭并废弃迟到读取。隐藏时不随聚焦或状态变更继续读日志。
- 保留 store 原有未知命令、原幂等键、成功后状态核对和身份隔离。
- 定位等待 DOM 更新时，同时校验导航代次、身份、宠物和目录；避免快速切区后隐藏卡片抢焦点。不能仅靠 `isConnected` 或尚未更新的隐藏样式判断。
- 导航支持左右方向键、Home、End、可见焦点与分区关联，定位避开顶部导航。尊重系统减少动态效果设置。
